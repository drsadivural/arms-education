# SQLの適用範囲とruntime権限
初期migrationと予約transactionの基礎実装を同梱。業務API/認証/ファイル/進捗判定/音声action serviceは実装対象。
DB role管理はprovider管理者権限で実施し、API roleにapp schema USAGE、必要tableの限定CRUD、予約関数EXECUTEのみ付与する。予約table直接変更は予約serviceに限定し、emit/expire内部関数を一般クライアントに公開しない。audit_eventsはINSERT/SELECTだけ、通常roleはUPDATE/DELETE不可。users/organizations/web_sessionsはtenant RLS対象外なので汎用CRUD APIを作らず専用認証repositoryで絞る。
runtime roleが予約関数内tableを操作するための権限を持つことと、外部クライアントがSQL/DBに接続できることは別。SQL関数はSECURITY INVOKER。Workerが本人/tenant contextを検証して同一transactionへ設定する。public Data APIでRPC公開しない。
003_supporting_workflows.sqlにクラス移動・定員削減・ロール整合・教材/quizバージョン制約・冪等/移行サポートtableを含む。transfer_student関数はadminだけが実行でき、旧新クラスをUUID順にロックして移動する。
program_versions自体の公開後policy/状態遷移、教材/出席/テスト/課題のunit完了条件、inactive講師枠停止はdomain serviceの責務。公開サービスはDB transactionでdraft単元/教材/正答/scanを検証しpublishedへ固定する。
expiryをchange_reservationで検出後に例外を出す場合、そのtransactionはrollbackする。APIは期限切れを別の成功transactionで確定し、409 responseはそのcommit後に返す。cronもslotロックでexpire_slotを実行する。複数slotの古いpendingによりstudentの時間重複constraintが残るケースは予約前に対象ユーザーのexpired pendingをslot ID昇順でロックし解放してからcreate関数を呼ぶ。DB行ロック順序を統一しdeadlockにbounded retryする。
